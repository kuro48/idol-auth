Mental model

共有アカウントとアプリ連携を理解する

idol-authでは、ユーザーの本人アカウントと、各アプリでの利用関係を分けて扱います。 アプリは必要な範囲の認可を受け、ユーザー本人はアカウントセンターから連携を管理できます。

主要な用語

用語 説明
共有アカウント ユーザーがidol-auth上で持つ本人アカウントです。メール、パスワード、MFA、基本プロフィールを管理します。
アプリ idol-authに接続する第三者サービスです。アプリごとにClient IDとredirect URIを持ちます。
アプリ連携 共有アカウントが特定アプリを利用できる状態です。退会や解除はこの連携を無効化する操作です。
同意 third-partyアプリが要求するスコープに対し、ユーザーが許可する操作です。
Management Token 自アプリの連携ユーザーだけを扱うためのサーバー側tokenです。

認証フロー

sequenceDiagram actor User as ユーザー participant App as あなたのアプリ participant Auth as idol-auth User->>App: ログインを開始 App->>Auth: Authorization Code + PKCE Auth->>User: ログイン / MFA / 同意 Auth-->>App: authorization code App->>Auth: token exchange Auth-->>App: access token / id token App->>User: アプリセッションを開始

アプリ側の責務

  • ユーザーをidol-authの認可画面へ正しく遷移させる。
  • callbackでstateを検証し、認可コードを安全に処理する。
  • ID tokenやUserInfo相当の情報を、自アプリのユーザー表現に対応付ける。
  • 退会導線では、共有アカウント削除ではなく自アプリの連携解除を使う。
  • tokenとsecretを用途に応じてサーバー側または安全なstorageに保管する。
