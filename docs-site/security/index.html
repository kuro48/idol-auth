Integration security

安全に連携するためのチェックリスト

OAuth2/OIDC連携では、redirect URI、state、PKCE、token保管、secret管理の扱いが重要です。 このページは第三者アプリ側で守るべき実装上の注意をまとめています。

OAuth2/OIDC

  • Authorization Code + PKCE を使ってください。
  • callbackでは必ず state を検証してください。
  • redirect URI は完全一致で登録し、任意の外部URLへ転送できる設計を避けてください。
  • 必要最小限のscopeだけを要求してください。

Secretとtoken

  • Client Secret はconfidential clientのサーバー側だけで保管してください。
  • SPAやネイティブアプリにClient Secretを含めないでください。
  • Management Tokenはブラウザやモバイルアプリへ渡さないでください。
  • access token、refresh token、session tokenをURL query、ログ、分析イベントに出さないでください。
  • refresh tokenを使う場合は失効と再認証の導線を用意してください。

ユーザー体験

  • ログアウト後はアプリ側セッションも明示的に終了してください。
  • アプリ退会と共有アカウント削除を分けて説明してください。
  • 連携解除されたユーザーに対して、再ログインまたは再連携の導線を用意してください。
  • MFAやパスワード変更はidol-authのアカウントセンターへ案内してください。

本番前レビュー

公開前に、redirect URI、Secretの保管先、tokenログ出力、CORS設定、退会時の連携解除、エラー表示の情報量を確認してください。
