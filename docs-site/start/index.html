Start guide

最初の連携を作る

このページでは、アプリ登録、クレデンシャル保管、ログイン導線、callback処理、 本番前チェックまでの流れを説明します。公開APIの詳細仕様はAPIリファレンスに集約しています。

導入フロー

  1. アプリを登録する。 idol-auth の開発者画面からアプリ名、種別、redirect URI、logout後の戻り先を登録します。
  2. Client IDを保存する。 Webサーバー型のアプリではClient Secretも保存します。SPAやネイティブアプリにSecretを埋め込まないでください。
  3. ログインボタンを実装する。 Authorization Code + PKCEでidol-authの認可画面へ遷移します。
  4. callbackで認可コードを処理する。 stateを検証し、認可コードをトークンに交換します。SDKを使う場合はこの処理を簡略化できます。
  5. 必要な連携管理を追加する。 ユーザー一覧、連携解除、公開プロフィール参照が必要な場合はManagement Tokenをサーバー側で使います。

アプリ登録で決めること

項目 決め方
アプリ種別 Web、SPA、ネイティブ、サーバー間連携など、実際の配布形態に合わせます。
Redirect URI callbackを受け取るHTTPS URLを完全一致で登録します。ローカル開発用URLは本番URLと分けて管理します。
Logout後の戻り先 ユーザーがログアウト後に戻るアプリ側URLを登録します。
Scopes 必要最小限にします。refresh token が不要なら offline_access を要求しない設計にします。

発行される情報

Client ID

認可リクエストで使います。ブラウザに露出してもよい識別子です。

Client Secret

confidential client向けです。サーバー側だけで保管し、SPAやネイティブアプリに含めないでください。

Management Token

自アプリの連携ユーザーを管理するためのBearer tokenです。必ずサーバー側で扱います。

App ID

管理画面やサポート問い合わせで対象アプリを特定するために使います。

Secret類は発行後に再表示されない前提で扱ってください。公開リポジトリ、フロントエンドbundle、ログ、分析イベントには含めないでください。
